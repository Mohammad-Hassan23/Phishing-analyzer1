Does the analyser really behave as described?

These are the same checks that run on the command line during development, running here in your browser. They verify that the six demonstration emails produce the results the interface claims, that the scoring arithmetic is correct, that the rules do not fire on ordinary messages, that the engine never crashes on strange input, and that no file in this project contains a network call.

    i

    Why these checks matter

    A security tool that quietly gives wrong answers is worse than no tool at all, because people trust it. These checks exist so that any change to the rulebook which starts producing false alarms - or stops catching something it used to catch - fails loudly instead of going unnoticed.

    Educational triage tool. It identifies warning signs; it cannot determine whether an email is malicious.
